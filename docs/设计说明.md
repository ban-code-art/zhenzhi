## 1. 设计目标与原则

- **单机离线**：不依赖任何服务器与网络，所有数据落本机 SQLite。
- **分层清晰**：界面、业务、数据访问分离，便于三人并行开发。
- **契约先行**：数据模型与公共接口先冻结，再各自实现。
- **可验证**：核心链路（建库、读写、登录）有可执行的验证手段。

## 3. 总体架构

单模块、分层架构：

```
Compose UI (Screen)
        │  事件 / collectAsState
        ▼
ViewModel (StateFlow)
        │  调用
        ▼
Repository（业务规则：校验、散列、组卷/判分边界）
        │
        ▼
DAO（Room）
        │
        ▼
SQLite（acupuncture.db）
```

- **界面层**：`ui/*`，只负责渲染与事件转发。
- **业务层**：ViewModel + Repository；密码散列、输入校验、统计计算在此。
- **数据层**：DAO + Entity + `AppDatabase`；外键、索引、schema 导出。
- **会话层**：`SessionManager`（DataStore）保存当前用户 id。

## 5. 数据设计

详细字段见 `docs/数据模型评审.md`，此处为设计要点。

### 5.1 表与关系

```
users 1 ──< test_records 1 ──< test_answers >── 1 questions
users 1 ──< favorites >── 1 questions
users 1 ──< study_progress >── 1 chapters
chapters 1 ──< questions
```

| 表 | 主键 | 关键约束 |
| --- | --- | --- |
| users | id | `username` 唯一 |
| chapters | id | `order_index` 唯一 |
| questions | id | 外键 → chapters（SET NULL）；`(type, enabled)` 索引 |
| test_records | id | 外键 → users（CASCADE）；`(user_id, started_at)` 索引 |
| test_answers | id | 外键 → test_records（CASCADE）、questions（RESTRICT）；`(test_id, question_id)` 唯一 |
| favorites | id | `(user_id, question_id, source)` 唯一，允许收藏与错题并存 |
| study_progress | id | `(user_id, chapter_id)` 唯一 |

### 5.2 设计决策

- **时间**统一为 Unix 毫秒（INTEGER）。
- **布尔**用 0/1；Room 侧映射为 `Boolean`。
- **结构化字段**用 JSON 字符串：
  - `questions.answer` 按题型存不同结构；
  - `questions.synonyms` 与填空的每个空一一对应。
- **软删除**不做，直接物理删除。
- **题库导入**计划采用 JSON 首次导入，便于内容维护。
- **头像**：`users.avatar_id`（0=昵称首字/自定义图，1–6=内置头像）+ `users.avatar_path`（自定义图片文件名，读取时解析到应用私有目录 `files/avatars/`）；数据库 v3，通过 `MIGRATION_1_2`、`MIGRATION_2_3` 增加。
- **schema 导出**：`app/schemas/.../1.json`、`2.json`、`3.json` 随仓库保存，便于后续迁移。

## 6. 关键流程

### 6.1 注册

1. 界面校验用户名格式、密码强度、昵称长度。
2. `UserRepository.register` 检查用户名是否已存在。
3. 生成 16 字节随机盐，PBKDF2 计算散列。
4. 写入 `users`（只存 `password_hash` + `salt`）。
5. `SessionManager.login(userId)` 写入会话 → 进入主界面。

### 6.2 登录

1. `UserRepository.login` 按用户名查用户。
2. 用库中盐重算散列，`MessageDigest.isEqual` 常量时间比较。
3. 成功写入会话；失败返回统一提示「用户名或密码错误」。

### 6.3 启动与会话恢复

`MainActivity` 读取 `SessionManager.currentUserId`：

- 有值 → 直接进入主界面；
- 无值 → 登录页；
- 读取期间显示加载指示器，避免闪屏。

### 6.4 登出

`设置 → 退出登录` → `SessionManager.logout()` 清除键值 → 导航回登录页并清空返回栈。
（该流程已在清理阶段修正：确保**先清会话再跳转**。）

### 6.5 修改密码

1. 校验原密码（重算比对）。
2. 校验新密码规则与二次确认。
3. 生成新盐 + 新散列，更新 `password_hash/salt/updated_at`。

### 6.6 「我的」统计

- **学习天数**：`test_records` 已交卷记录按本地日期去重计数。
- **连续打卡**：从今天（或昨天）向前数连续日期。
- **已完成章节**：`study_progress.completed = 1` 计数。
- **收藏 / 错题**：`favorites` 按题目去重计数（错题限 `source='WRONG'`）。

### 6.7 成绩列表与详情

- 列表：`test_records.status='SUBMITTED'`，按 `started_at DESC`。
- 详情：`test_answers` 按 `order_index` + `questions` 拼接题干/答案/解析。

## 7. 导航与界面设计

### 7.1 顶层路由（`AppNavHost`）

| 路由 | 页面 |
| --- | --- |
| `login` | 登录 |
| `register` | 注册 |
| `home` | 主界面（四页框架） |

登录/注册成功用 `popUpTo(login){inclusive=true}` 清理返回栈。

### 7.2 主界面

- 自定义底部导航 `AppBottomBar`：白色圆角悬浮栏、绿色选中态 + 下划线指示。
- 四个标签：知识学习 / 随机测试 / 记录题目 / 我的。
- 标签内容用 `when` 切换，`rememberSaveable` 保留选中项。

### 7.3 「我的」子页

- `mineStack: SnapshotStateList<MineDestination>` 作为子页返回栈。
- `BackHandler` 接管系统返回；子页隐藏底栏。
- 覆盖：个人信息、修改密码、我的课程、收藏、错题、学习记录（成绩列表/详情）、消息通知、设置。

### 7.4 设计系统

| 元素 | 规范 |
| --- | --- |
| 认证页背景 | 薄荷绿竖向渐变 |
| 认证卡片 | 白色、28dp 圆角、阴影 |
| 输入框 | 16dp 圆角、浅绿底、左侧图标 |
| 主按钮 | 绿色渐变药丸（56dp 高） |
| 「我的」背景 | `#F3F8F5` |
| 品牌绿 | `#4FA98C` |
| 卡片 | 白色、16–28dp 圆角、轻阴影 |
| 底栏 | 白色、顶部圆角、图标 24dp、文字 11sp |

### 7.5 适配策略

- 尺寸用 `dp`/`sp`，宽度用 `fillMaxWidth`/`weight`，高度溢出用 `verticalScroll`/`LazyColumn`。
- 底栏加 `navigationBarsPadding()` 适配手势条与刘海。
- 当前为**手机优先**布局；平板/折叠屏尚未做 `WindowSizeClass` 多栏适配。

## 8. 安全设计

- **密码**：`PBKDF2WithHmacSHA256`，12 万次迭代，256 位输出，16 字节 `SecureRandom` 盐；逐用户独立盐。
- **比较**：`MessageDigest.isEqual` 常量时间比较，降低时序侧信道风险。
- **存储**：数据库只存 `password_hash` 与 `salt`；不存明文。
- **会话**：DataStore 仅保存当前用户 id，不保存密码。
- **网络**：应用未申请网络权限，数据不出本机。
- **声明**：设置 → 关于中展示"仅供学习参考，不构成医疗建议"。

## 9. 状态管理

- 每个页面一个 `ViewModel`，暴露 `StateFlow<UiState>`。
- 界面用 `collectAsState()` 订阅，事件通过方法回调。
- ViewModel 通过 `ViewModelProvider.Factory` 注入 `Repository/DAO/SessionManager`。
- 一次性操作（保存、登录）使用回调 `onDone/onSuccess` 触发导航。

## 11. 构建与运行

### 11.1 环境

- Android Studio（含 JBR）
- Android SDK：platform 37、build-tools 36
- 模拟器：`medium_phone`（Android 16 / API 36）或真机

### 11.2 命令行

```powershell
$env:JAVA_HOME="C:\Program Files\Android\Android Studio\jbr"
.\gradlew.bat :app:assembleDebug
.\gradlew.bat :app:installDebug
```

### 11.3 产物

- Debug APK：`app/build/outputs/apk/debug/app-debug.apk`（可直接装手机）
- Release：当前未配置签名，`assembleRelease` 产物为 unsigned，不能直接安装；正式交付需配置 keystore。

### 11.4 安装到手机

把 APK 传到手机（微信/QQ/网盘/邮件）→ 允许安装未知来源 → 安装即可，**无需数据线与电脑**。

## 12. 已知限制与后续扩展

| 限制 | 影响                 | 后续方案 |
| --- |----------------------| --- |
| 知识学习/随机测试/记录题目为占位页 | 仅账号与「我的」可用 | 成员二/三按接口实现 |

| 无数据导出/备份 | 卸载即丢失           | 后续可加导出 JSON |

## 13. 团队协作接口

成员二/三直接依赖以下能力，**请勿绕过 Repository/DAO 直接写 SQL**。

### 13.1 题库与章节（成员二）

| 能力 | 接口 |
| --- | --- |
| 批量导入章节 | `ChapterDao.insertAll(List<ChapterEntity>)` |
| 章节列表 | `ChapterDao.observeEnabled()` / `getAll()` |
| 批量导入题目 | `QuestionDao.insertAll(List<QuestionEntity>)` |
| 按章节取题 | `QuestionDao.findByChapter(chapterId)` |
| 写学习进度 | `StudyProgressDao.upsert(...)` |

### 13.2 测试与复习（成员三）

| 能力 | 接口 |
| --- | --- |
| 按题型抽题 | `QuestionDao.randomByType(type, limit)`、`countByType(type)` |
| 创建测试记录 | `TestRecordDao.insert(...)` / `update(...)` |
| 保存作答明细 | `TestAnswerDao.insertAll(...)` |
| 断点续答 | `TestRecordDao.findInProgress(userId)` |
| 收藏/错题 | `FavoriteDao.insert(...)`、`delete(...)`、`findBySource(...)` |

### 13.3 用户与成绩（成员一）

| 能力 | 接口 |
| --- | --- |
| 用户资料 | `UserRepository.findById / updateNickname` |
| 改密 | `UserRepository.changePassword` |
| 成绩展示 | `TestRecordDao.observeSubmittedByUser`、`TestAnswerDao.findByTest` |
